{#- ==================== Flujo de trabajo ==================== -#}

Flujo de trabajo recomendado

  1. Prepara el catálogo. Crea primero las categorías y los laboratorios; después los equipos, asignándoles su categoría y su laboratorio. Así los préstamos y las reservas podrán referenciarlos.
  2. Registra a los prestatarios. Son las personas que reciben un espacio o un equipo: docentes, estudiantes o personal. No necesitan cuenta en el sistema; solo sus datos de contacto.
  3. Reserva laboratorios. Indica laboratorio, prestatario, fecha y hora. La duración viene con el valor estándar de 70 minutos, pero puedes cambiarla. Si el horario está ocupado, el sistema te ofrecerá alternativas.
  4. Presta equipos. Selecciona un equipo disponible y el prestatario. El equipo pasa a PRESTADO y no podrá prestarse otra vez hasta que se devuelva.
  5. Registra las devoluciones. Desde el listado de préstamos activos, con el botón Devolver. El equipo vuelve a DISPONIBLE y se guarda la fecha.
  6. Consulta el historial y los indicadores. El panel resume la actividad; el historial permite filtrar por tipo, estado, prestatario, recurso y fechas, y exportar a CSV.
{#- ==================== Reglas que conviene conocer ==================== -#}

Reglas del sistema

{{ ic.icono('reservas') }} Solapamientos

Dos reservas del mismo laboratorio y fecha chocan cuando inicio existente < fin nueva y fin existente > inicio nueva.

  • {{ ic.icono('correcto') }} 08:00–09:10 y 09:10–10:20 → permitido
  • {{ ic.icono('error') }} 08:00–09:10 y 09:09–10:19 → rechazado

Solo bloquean las reservas en estado CONFIRMADA o ACTIVA: al cancelar una reserva, la franja queda libre de inmediato.

{{ ic.icono('equipos') }} Estados de los equipos

  • {{ ic.icono('correcto') }} DISPONIBLE → se puede prestar.
  • {{ ic.icono('correcto') }} PRESTADO → está fuera; no se puede volver a prestar ni eliminar.
  • {{ ic.icono('correcto') }} MANTENIMIENTO / DAÑADO / INACTIVO → fuera de servicio.

Un equipo con préstamo activo no aparece en el formulario de préstamos.

{{ ic.icono('escudo') }} Roles

  • {{ ic.icono('correcto') }} ADMINISTRADOR: todo, incluidos usuarios, eliminaciones y auditoría.
  • {{ ic.icono('correcto') }} OPERADOR: prestatarios, reservas, préstamos y devoluciones. No ve usuarios ni puede eliminar catálogo.

El rol se comprueba contra la base de datos en cada acción, así que un cambio de permisos surte efecto de inmediato.

{{ ic.icono('alerta') }} Avisos automáticos

  • {{ ic.icono('correcto') }} Préstamos con más de {{ alertas.dias_limite }} días sin devolver: se destacan en rojo.
  • {{ ic.icono('correcto') }} Reservas programadas para hoy.
  • {{ ic.icono('correcto') }} Laboratorios con alta ocupación esta semana ({{ alertas.umbral_saturacion }} reservas o más).

El número de la campana de la barra superior indica cuántos avisos hay pendientes.

{#- ==================== Preguntas rápidas ==================== -#}

Dudas frecuentes

¿Cómo busco algo rápido sin recorrer los menús?

Presiona Ctrl+K y escribe. Encontrarás secciones, acciones y también registros concretos: prestatarios, equipos, laboratorios y reservas.

¿Por qué no me deja eliminar un laboratorio?

Porque tiene equipos o reservas asociadas. El sistema protege la integridad de los datos: primero reasigna o elimina lo que depende de él. Es una salvaguarda, no un error.

¿Puedo exportar lo que estoy viendo?

Sí. El botón Exportar CSV de cada listado descarga lo que tienes filtrado en ese momento. El archivo se abre directamente en Excel con las columnas y los acentos correctos.

¿Qué pasa si dos personas guardan una reserva a la vez?

La comprobación de solapamiento y la inserción se hacen dentro de la misma operación sobre la base de datos, así que la segunda petición ve la primera y se rechaza. Si necesitas coordinación a mayor escala, el sistema está preparado para añadir una restricción de unicidad.

¿Cómo recupero la base de datos si algo va mal?

Con python init_db.py desde la carpeta del proyecto. Reconstruye el esquema completo con los datos de ejemplo a partir de schema.sql. Haz copia del archivo database/techloan.db antes si tienes datos reales.
